# 使用指南

[返回 README](../README.md) · [配置参考](configuration.md) · [开发说明](development.md)

## 玩家兑换

1. 将兑换券放入主背包或快捷栏。
2. 执行 `/tianjiredeem open`，选择建材分类。
3. 在九列图标目录中选择商品；将鼠标移到图标上可查看名称，指定画作还会显示变体 ID。
4. 确认物品预览和当前券数，使用滑块选择 **1～64 张券**。
5. 点击“兑换”。每张券获得 **64 个所选物品**，例如使用 3 张券获得 192 个。

兑换成功后会播放音效，刷新当前商品页的券数，滑块恢复为 1，可以继续兑换。券不足或提交数量无效时会播放失败音效，并在当前页显示原因。点击“返回”可回到当前分类，再返回分类列表。

页面上的券数在打开或刷新商品页时读取；点击兑换时会重新检查背包，不以页面上此前显示的数值结算。按钮有效期为 10 分钟，长时间停留后若无法操作，请重新执行 `/tianjiredeem open`。

## 命令与权限

下表使用游戏内命令写法；服务器控制台执行时省略开头的 `/`。`<参数>` 必填，`[参数]` 可选，输入时不带尖括号或方括号。

| 命令 | 作用 | 权限 | 默认授权 |
| --- | --- | --- | --- |
| `/tianjiredeem` | 显示用法 | 无 | 所有人 |
| `/tianjiredeem open` | 打开自己的兑换界面 | `tianjiredeem.use` | 所有玩家 |
| `/tianjiredeem open <player_name>` | 为指定在线玩家打开界面 | `tianjiredeem.admin.open` | OP |
| `/tianjiredeem give <amount> [player_name]` | 发放兑换券 | `tianjiredeem.admin.give` | OP |
| `/tianjiredeem reload` | 重载配置和消息 | `tianjiredeem.admin.reload` | OP |

入口只有 `/tianjiredeem`，没有命令别名。

### 打开界面

```text
/tianjiredeem open
/tianjiredeem open Steve
```

指定玩家时需输入完整的在线游戏名，匹配不区分大小写，不支持名称片段或离线玩家。即使指定的是自己，也需要 `tianjiredeem.admin.open`。

目标玩家仍须拥有 `tianjiredeem.use`。管理员替其他玩家打开界面只需 `tianjiredeem.admin.open`，无需自己拥有使用权限。已打开界面的玩家若被撤销使用权限，下次操作时界面会关闭并提示无权限。

控制台必须指定目标玩家。

### 发放兑换券

```text
/tianjiredeem give 16
/tianjiredeem give 16 Steve
```

数量必须为正整数。管理员在游戏内省略目标时发给自己；控制台必须指定在线玩家。发券数量不受单次兑换 64 张的限制，插件会按堆叠上限拆分发放，放不下的部分掉落在目标玩家脚边。

发券权限与使用权限独立，接收兑换券不要求玩家拥有 `tianjiredeem.use`。

### 接入活动或菜单插件

可让其他插件以控制台身份执行命令。例如，给在线玩家 Steve 发 8 张券，或打开他的兑换界面：

```text
tianjiredeem give 8 Steve
tianjiredeem open Steve
```

将 `Steve` 按调用方插件的玩家占位符语法替换。TianjiRedeem 本身不提供活动奖励规则、经济账户或离线发券队列。

### 命令补全

Tab 补全只显示当前执行者有权限使用的子命令，并提供匹配的在线玩家名。子命令前缀补全区分大小写，建议输入小写；命令执行与玩家名补全不区分大小写。

## 兑换券与背包规则

- 插件发放的券使用砖纹旗帜图案，最多堆叠 64 张。只有插件标记的物品才会计为券，单纯改名或复制描述无效。
- 每个有效物品单位计为 1 张券，不同外观的有效券可以共同支付。修改券名称或描述后，旧券仍有效，但不会自动更新外观或堆叠上限；只有数据相同的券才能合并。
- 结算只统计主背包和快捷栏，忽略装备、副手、鼠标光标、末影箱，以及箱子、潜影盒等容器内部的券。
- 库存不足时不会扣券或发货；足够时按背包槽位顺序扣除，剩余券保留原有数据。
- 产物按正常堆叠规则放入背包，溢出部分掉落在玩家脚边。不可堆叠物品也按每张券 64 个发放，兑换前请留意空间。
- 指定画作的预览与发放物品都保留配置的画作变体。

供其他插件开发者参考的券标记格式见[开发说明](development.md)。

## 修改配置与重载

编辑服务器中的 `plugins/TianjiRedeem/config.yml` 或 `messages.yml` 后执行：

```text
/tianjiredeem reload
```

插件同时读取并校验两份文件，成功后更新商品、分类、券外观、音效及消息。新外观用于后续发放的券。已打开的旧界面在下次点击时关闭，玩家重新执行 `open` 即可使用新界面。

如果任一文件校验失败，命令会显示文件和字段位置，当前生效配置与界面继续保留。修正文件后可再次重载，磁盘上的错误内容不会被自动还原。

启动阶段遇到配置错误时，插件会停止启用；根据服务器日志修正配置后重启服务器。字段、示例和升级步骤见[配置参考](configuration.md)。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 提示“兑换券不足”，但手上有券 | 将副手、光标或容器内部的券移入主背包；普通改名物品不会被识别。 |
| 发券或兑换后背包里数量不够 | 检查玩家脚边的掉落物，背包溢出部分会掉落。 |
| 玩家无法打开或继续使用界面 | 检查目标玩家的 `tianjiredeem.use`；替他人打开还需执行者有 `tianjiredeem.admin.open`。 |
| 界面放置一段时间后按钮无响应 | 按钮会过期，重新执行 `/tianjiredeem open`。重载成功后也需重新打开。 |
| 新增分类没有出现 | 空分类不会显示；确认分类下有商品，并且重载成功。 |
| 新增商品图标缺失或显示异常 | 有些物品的纹理与 ID 不同，需要补充源码中的图标映射，见[开发说明](development.md)。 |
| 修改配置后没有变化 | 确认编辑的是服务器插件数据目录中的文件、重载已成功，并重新打开界面。旧券外观不会自动更新。 |
| 听不到兑换音效 | 检查 `sounds` 的音量和音效 ID，并检查客户端主音量；音效只向操作玩家播放。 |
| 命令提示执行失败 | 查看服务器日志中的具体异常；若启动时已有配置报错，先按提示修正并重启。 |
